# three.js for the homepage World

The homepage World (a 3D voxel town behind the content) is rendered with three.js. This does not conflict with ADR 0001: three.js is a rendering library, not a UI framework. It holds no component state, does no hydration, and renders nothing the page's content depends on. Every word on the homepage is still static HTML from Astro. three.js is loaded only on `/`, through a dynamic import that runs after the content has painted. Without WebGL or JavaScript, the page shows a CSS gradient instead. Characters are authored as text voxel grids in TypeScript behind a `loadCharacter(source)` seam, so a file-based model format (for example MagicaVoxel `.vox`) can be added later without changing the scene code.

**Update (2026-10-18):** Cast Members are no longer voxel grids. They are community glTF models loaded through the same `loadCharacter` seam; see ADR 0005.

**Update (2026-10-19):** The voxel town and the camera path are gone. The World is now a procedural low-poly meadow, seen from one fixed camera (`docs/superpowers/specs/2026-10-19-meadow-world-design.md`). The owner found the town blocky, flat and busy behind the cards, and the camera moving between Steps distracting. Everything is generated in code from `src/world/meadow/layout.ts`, with no model files, so the download stays small and every composition number can be tuned and unit tested. The ambient motion runs from one clock: grass and fireflies sway in vertex shaders, while trees and clouds are moved each frame on the CPU. Grass is the main cost, so it has three quality tiers (60,000 / 25,000 / 8,000 blades). The starting tier comes from device hints, and drops at runtime when frames run slower than about 45 fps. Later options: CC0 stylised props can replace the procedural trees through `createTree`, and a meadow built in Blender and exported as one GLB is possible if more art control is worth a bigger download.
